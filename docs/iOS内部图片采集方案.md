# iOS 内部图片采集方案

采集方式已确定：dylib 加载到用户自己的 App 中，通过 UIKit 将该 App 当前活动的 `UIWindow` 渲染为一张 PNG。输出包含窗口内可见的文字、按钮、图片和布局。后台支持点击获取一张，或在有效会话中目标每 3 秒获取一张。

## 本地工程检查

| 项目 | 检查结果 |

| 工程 | `ios/jk/jk.xcodeproj` |
| 类型 | MonkeyDev 构建的 Objective-C++ 动态库 |
| 包依赖 | MobileSubstrate |
| 最低部署版本 | iOS 15.6 |
| 加载入口 | `ios/jk/jk/jk.mm`，`+load` 延迟 3 秒初始化 |
| 过滤配置 | `jk.plist` 中为占位 Bundle ID |
| 已链接框架 | Foundation、UIKit、CoreGraphics、ImageIO、Network、Security |

已实现窗口采集、手机自主任务、本地任务与指令持久化、HTTPS 图片上传、设备注册与 WSS，并已和 Go 服务器完成真实协议联调。手机端定位采集仍待接入。[接入说明](iOS接入说明.md)、[服务器说明](../server/README.md)

采集端与自有 App 处于同一进程，可通过项目提供的接口取得当前活动窗口。当前工程的 MobileSubstrate 包装与自有 App 的实际 dylib 集成方式分别处理；后续按主项目的链接、签名和加载配置接入。网络协议和采集调度封装在 dylib 内，加载后自动初始化；主项目可选提供窗口选择信息。

由 `+load` 调度到主队列，3 秒后自动初始化；主项目不用调用启动。服务器地址从主 App 的 `JKMonitor.plist` 读取，设备身份保存在 Keychain，窗口提供器可选配置。初始化幂等，仅收到采集指令后才开始生成图片。

## 界面渲染为 PNG

`capture_source=uikit_window`、`capture_scope=active_window` 表示将当前活动窗口的完整可见区域渲染为位图。输出尺寸按窗口 bounds、方向和配置的最大长边确定，保持比例；首版不裁切指定控件，不自动滚动拼接长图。

UIKit 的 `drawHierarchy(in:afterScreenUpdates:)` 将视图层级绘制到图形上下文；返回值可用于判断是否缺少视图图像数据。`afterScreenUpdates=false` 使用当前层级状态，可能不含最近更新。因此必须记录采集时间和应用状态，不能把缓存视图认作刚刚更新的业务内容。[Apple 视图绘制说明](https://developer.apple.com/documentation/uikit/uiview/drawhierarchy(in:afterscreenupdates:))

使用 `UIGraphicsImageRenderer` 规定输出大小与缩放，并生成 PNG。视图和 UIKit 相关操作放在主线程，编码和上传按照可安全转移的图像数据安排在工作队列，避免网络阻塞主线程。[Apple 图片渲染器说明](https://developer.apple.com/documentation/uikit/uigraphicsimagerenderer)

采集流程：

```text
收到有效 GET_IMAGE 或会话采集时机
          ↓
检查本进程运行状态和允许采集的视图
          ↓
通过自有 App 的窗口提供器取得当前活动 UIWindow
          ↓
主线程按完整窗口 bounds 和输出尺寸生成位图
          ↓
检查生成结果与采集状态，生成报告 ID
          ↓
编码为 PNG，通过 HTTPS 上传
```

窗口选择以自有 App 提供的窗口为准。默认回退规则为：只在 `foregroundActive` 的 UIWindowScene 内查找唯一的 key window；不存在可用窗口时等待前台，存在多个候选时返回 `CAPTURE_TARGET_AMBIGUOUS`，由主项目明确目标。不能使用所有场景的第一个窗口作为默认目标。

采集时重新获取窗口，避免页面切换后继续使用旧窗口。使用选定窗口的完整 bounds 绘制，同一窗口内的导航栏、标签栏和呈现内容应一同出现在 PNG 中。弹窗如果创建了独立活动窗口，则按主项目当前窗口选择规则采集该窗口；不自动合成多个窗口。

视频、WebView、Metal、自定义图层和受保护内容单独验证。不能把普通 UIKit 视图测试成功推广为所有渲染内容都可获取；不完整时返回 `CAPTURE_INCOMPLETE` 或声明不支持。

`snapshotView(afterScreenUpdates:)` 返回视图对象，不是可直接上传的 PNG。图层 `render(in:)` 是另一种渲染手段，不能无条件当作更完整的兜底；其动画与图层合成效果需要验证。[Apple 图层渲染说明](https://developer.apple.com/documentation/quartzcore/calayer/render(in:))

## 输出和完成标准

- 每次成功采集返回一张完整活动窗口 PNG，不逐张提取其中的图片对象。
- 输出比例跟随选定窗口，最大像素尺寸按服务端配置缩放。
- 记录窗口采集时间、像素尺寸、方向、来源、应用状态和缓存标记。
- 图片中存在已知缺失区域时返回 `CAPTURE_INCOMPLETE`，不冒充完整画面。
- 窗口切换、旋转和停止会话均要在上传前再次核对，避免把旧会话结果送入新会话。
- 服务器确认文件与报告已保存后，单次获取任务才显示成功。

## 灭屏和后台状态

UIKit 采集不需要建立系统整机屏幕广播，但依然依赖所在进程能运行、视图存在且渲染可用。普通 iOS 后台执行规则不会因为改用 UIKit 而消失。[Apple 后台执行说明](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)

| 状态 | 首版执行规则 |
| --- | --- |
| App 前台且视图可用 | 允许按有效指令采集 |
| App 暂时 inactive | 等待恢复 active；在有效期内重新检查 |
| App 进入后台或没有可用场景 | 暂停界面实时采集，报告 `waiting_foreground` |
| 进程被挂起或退出 | 不承诺心跳、采集和收令；服务器保留未过期任务 |
| 缓存图片可用 | 仅在允许缓存的查询中返回原图片和原时间 |
| App 再次前台运行 | 先同步服务器归属和会话状态，再执行仍有效任务 |

后台状态不直接等同于锁屏。没有可靠来源时，`screen_state=unknown`。即使某一设备环境能在背景读取旧视图，也需要区分数据新鲜度，不能默认开启灭屏每 3 秒采集。

锁屏后能否读取图片文件还可能受文件保护状态影响。不可用时返回具体原因，等待应用正常恢复后重新检查。

## 每 3 秒采集的调度

收到任务启动后先原子保存，再确认接收。手机使用单一调度器，每 3 秒尝试采集一次；已有采集或上传未结束时跳过该次时机。每次先核对任务有效性和前台状态，再访问视图。网页关闭不影响任务，App 重启后恢复已保存任务，停止或到期记录防止迟到的开始消息重新启动。

上传仅允许一个进行中帧和一个最新待上传帧。每帧包含来源、会话编号、序号、采集时间和 `is_cached`。采集失败上报原因并适当降低重试频率，不能每 3 秒无限弹出提示或创建新任务。

后台网页展示“App 活动窗口”，包含“获取窗口图片”“开始实时查看”和“停止”操作。页面显示实际最后成功采集时间；设备恢复前台后，过期会话保持停止。

## 真机验证清单

先在自有 App 和一台目标 iPhone 上验证，再把支持能力接入后台：

1. 主项目加载 dylib，等待自动初始化，单次导出当前活动窗口，核对 PNG 尺寸、清晰度和颜色。
2. 验证弹窗、多 Scene、横竖屏、滚动列表和动画状态。
3. 分别测试 WebView、视频和自定义渲染区域，记录完整或不支持结果。
4. 每 3 秒运行 5 分钟，记录主线程耗时、编码耗时、内存、CPU 和网络吞吐。
5. 切到后台、锁屏、断网、恢复前台，核对暂停和任务过期处理。
6. 模拟重复指令、晚到开始、立即停止、设备转移，确认不会恢复旧任务。
7. 验证多个前台场景、独立弹窗窗口和窗口销毁，确认目标选择明确且不引用已释放窗口。

模拟器测试覆盖自动初始化、实际 PNG 生成、3 秒任务、非活动暂停与恢复、停止去重、任务跨进程重启恢复及本地 TLS/WSS 通信。真实锁屏、目标 App 特殊渲染区域、实际网络环境和发布签名仍需在主项目真机验证。
