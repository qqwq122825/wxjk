# iPhone 设备监控后台设计方案

版本：第一版设计草案。日期：2026 年 11 月 11 日。

设备使用统一服务器地址接入，新设备先进入总台。总台创建代理账号，将设备下发给代理；代理登录后，只能查看和操作自己名下的设备。设备上传图片和定位，后台支持单次获取图片、单次获取位置、开始和停止每 3 秒一次的实时图片会话。

图片采集方式已确定：dylib 加载到用户自己的 App 进程，使用 UIKit 将当前活动的 `UIWindow` 可见区域渲染为一张 PNG。界面内的文字、按钮和图片一起出现在输出中。具体接入与窗口选择见 [iOS 内部图片采集方案](iOS内部图片采集方案.md)。

## 需求和默认参数

| 项目 | 第一版约定 |
| --- | --- |
| 用户角色 | 总台管理员、代理 |
| 账号来源 | 总台创建代理，不开放公开注册 |
| 首次上线 | 自动登记到总台待分配列表 |
| 设备分配 | 总台手动或批量下发，不自动随机分配 |
| 图片格式 | PNG |
| 图片来源 | 自有 App 进程内当前活动的 UIWindow |
| 采集范围 | 活动窗口当前可见区域，输出单张完整窗口图片 |
| 实时图片间隔 | 目标每 3 秒一次，受客户端运行和上传能力影响 |
| 定位 | 单次请求，支持按授权和实际能力持续更新 |
| 指令接收 | WSS 实时通知，数据库保存，重连同步 |
| 无连接时通知 | 有相应 App 能力时接入 APNs，不以推送替代指令数据库 |

以下数值是首版可配置默认值，不是 iOS 后台执行保证：心跳 30 秒、连接无响应阈值 120 秒、在线指令确认等待 10 秒、单次图片请求有效期 120 秒、单次位置请求有效期 300 秒。实时任务由手机自主执行，不依赖网页续期；可选 `task_expires_at` 指定任务截止，不设置时持续到显式停止。图片和位置默认保留 7 天，容量评估后调整。

## 现有工程和接入边界

`ios/jk/jk.xcodeproj` 的产物是动态库，部署版本为 iOS 15.6。原包装目录声明 MobileSubstrate 依赖，过滤 Bundle ID 仍为占位值。新增的自有 App 接入路线通过独立构建脚本产出可嵌入 dylib，默认不执行原打包安装脚本。

当前已实现 Go 服务端、Vue 总台与代理网页、SQLite 持久化，以及 iOS 活动窗口采集、生命周期暂停恢复、手机自主任务、设备注册、Keychain 身份、WSS 和 HTTPS 图片上传。服务端位置接口已实现，手机端定位采集仍待接入。SQLite 及真实 dylib 与 Go 服务的协议联调已验证，公网部署和实际 iPhone 锁屏待现场验收。[服务器说明](../server/README.md)、[iOS 接入说明](iOS接入说明.md)

已有的 deb 和 zip 是打包文件，不能据此认定上述功能已经实现。接入目标已明确为用户自己的 App；实际加载和打包方式需与该项目匹配，不能直接把 MobileSubstrate 包装方式当作自有 App 的加载实现。设计中的能力需要由客户端显式上报，并在真机验证。

后端不绑定客户端实现语言。现有 Objective-C++ 工程可以作为采集端接入协议；若需要独立 App、推送身份或系统扩展，需要另外配置实际承载它们的 App。动态库不会因为加载进进程，就自动具有独立 App 的 APNs 身份和系统扩展能力。

## 总体架构

```text
总台和代理网页
      │ HTTPS API 和网页事件流
      ▼
Go 后端
  ├─ 账号和访问控制
  ├─ 设备登记与归属
  ├─ WSS 连接与心跳
  ├─ 指令和结果管理
  ├─ 实时图片会话
  ├─ 图片与定位接收
  └─ 过期清理与审计
      │
      ├─ PostgreSQL：账号、归属、指令、元数据
      ├─ 私有文件存储：PNG 文件
      └─ APNs：符合条件时通知客户端
      ▲
      │ WSS 指令与确认，HTTPS 数据上传
iPhone 客户端
  ├─ 身份与连接管理
  ├─ 指令去重与状态持久化
  ├─ 自有 App 活动 UIWindow 采集适配器
  ├─ 定位适配器
  └─ 生命周期与会话控制
```

首版采用 Go 和 Vue 3，默认使用 SQLite 方便本地运行，也可配置 PostgreSQL 驱动。当前为单个服务实例，内置指令重投和过期清理工作协程。PNG 起步存服务器私有磁盘，存储接口预留迁移对象存储的能力。使用反向代理终止 HTTPS 和 WSS。指令和分配关系不能仅存内存；Redis 留作后续多实例连接通知和缓存，不作为首版必需组件。

## 账号和访问控制

总台初始化账号由部署流程创建，首次登录修改密码。代理由总台创建，字段包括唯一登录账号、代理名称、初始密码、启用状态和备注。初始密码可随机生成，代理首次登录必须修改；总台只能重置密码，不能查看原密码。

| 操作 | 总台 | 代理 |
| --- | --- | --- |
| 创建和禁用代理 | 可以 | 不可以 |
| 查看待分配设备 | 可以 | 不可以 |
| 下发、回收和转移设备 | 可以 | 不可以 |
| 查看图片和定位 | 所有设备 | 自己名下设备的本次分配数据 |
| 请求图片、位置和实时会话 | 所有正常设备 | 自己名下正常设备 |
| 修改设备备注 | 可以 | 自己名下设备 |
| 查看审计记录 | 全部 | 仅自身操作记录 |

密码用 Argon2id 哈希保存。网页使用可撤销的服务端登录会话，Cookie 设置 HttpOnly、Secure 和合适的 SameSite，并对修改请求实施 CSRF 防护。禁用账号、重置密码时撤销会话。[密码存储依据](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

设备列表、详情、图片下载、定位查询、指令创建和网页事件订阅均在后端检查权限；不接受前端传入的代理 ID 作为授权依据。图片不放入公开静态目录。[访问控制依据](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

## 设备登记和分配

设备端首次显示唯一的服务器地址输入框，地址保存到本地，后续静默连接。设备首次接入时生成本地注册秘密，自动登记并换取独立设备令牌；服务端可选择开放待审批登记，或通过部署配置要求额外准入凭据。用户不输入代理账号或注册凭据。设备 ID 用于识别，不作为唯一认证凭据；设备令牌不包含可由客户端修改的代理归属。

设备 ID 在本地持久保存。同一设备重复注册返回已有登记状态，不创建重复设备。重装是否沿用旧身份由凭据恢复流程决定，不依赖可随意伪造的设备名称。注册准入凭据的发放方式在部署时确定。

```text
首次注册成功 → 总台待分配
总台选择设备与代理 → 事务内建立分配记录
代理刷新列表 → 看到设备
设备断线或重启 → 使用原设备身份，保留归属
回收 → 结束当前分配，回到待分配
转移 → 结束旧分配，创建新分配
```

一个设备同一时刻最多存在一条有效分配。使用设备行锁和数据库唯一约束保证并发安全。待分配和已分配是归属状态，与连接在线状态、设备是否停用分别保存。

回收、转移或禁用代理时，取消相关代理的待执行指令和实时任务。服务端立即撤销其读取和订阅权限，并拒收旧批次上传。设备收到撤销或停止状态后停止；设备无连接时，服务端无法保证立即停止其本地任务，停止指令需持久保存并在重连时下发。

历史数据关联采集发生时的分配批次。新代理默认只能查看新批次数据；总台可查看保留期内的历史。设备重连须先同步当前批次，旧批次结果不得自动挂到新代理名下；无法确认采集归属的补传结果隔离为总台可见或拒收。

## 心跳和连接状态

客户端运行期间建立 WSS，每 30 秒发送应用心跳。WSS 不可用且客户端仍有运行机会时，可使用 HTTPS 心跳并拉取待处理指令。两条通道共用设备身份、确认记录和去重逻辑，不创建两套指令。

后端以服务器接收时间更新 `last_seen_at`；有效心跳和通过认证的数据上报都能证明近期通信。另记 `last_heartbeat_at`、最近图片和位置接收时间，区分连接正常与数据停止更新。

| 展示状态 | 含义 |
| --- | --- |
| 已连接 | 当前连接代次有效，且最近 120 秒有应用层有效通信 |
| 当前无连接 | 未持有可用 WSS，保留最近联系时间 |
| 连接无响应 | 连接对象仍在，但超过阈值未收到应用通信，服务端关闭陈旧连接 |
| 未连接过 | 登记后尚无有效连接或心跳 |

WSS 断开不能推断手机已关机，也不能推断屏幕已锁定。普通 iOS App 在后台可能被系统挂起；即使启用后台定位，也不代表拥有任意后台运行能力。[iOS 后台执行与定位依据](https://developer.apple.com/documentation/corelocation/handling-location-updates-in-the-background)

同一采集端重新连接时生成新连接代次，旧连接的关闭事件不得覆盖新连接状态。当前首版只约定每个逻辑设备一个采集端；如需多个 App 采集端汇聚到一台手机，后续引入 `collector_id` 并独立计算各采集端状态。

## 指令队列和交付规则

| 指令 | 含义 |
| --- | --- |
| `GET_IMAGE` | 将自有 App 当前活动窗口渲染为一张 PNG |
| `GET_LOCATION` | 获取一次符合新鲜度要求的位置 |
| `START_IMAGE_SESSION` | 启动目标每 3 秒一帧的图片会话 |
| `STOP_IMAGE_SESSION` | 终止指定会话 |

第一版图片来源固定为 `capture_source=uikit_window`，范围固定为 `capture_scope=active_window`。客户端上报活动窗口采集能力，服务器按该能力派发指令。图片资源逐张导出和系统整机屏幕共享不进入第一版。

先在数据库事务中保存指令和投递事件，再通知连接。发送到 Socket 只代表发送尝试，不代表手机已接收。客户端回复接收确认，执行后上传结果；结果持久化后才显示成功。

```text
queued → received → running → succeeded
                    ├─ waiting_foreground
                    ├─ waiting_permission
                    ├─ failed
                    ├─ expired
                    └─ canceled
```

等待前台或授权后可在有效期内继续运行。失败、过期、取消和成功是终态。指令到期后不再启动采集；稍后到达的终态结果不能把指令改回执行中。若结果已经过期，保存迟到原因供审计，代理页面不把它当成本次请求成功。

连接有效、尚未收到确认时，每约 10 秒重投同一 `command_id`，直到确认、取消或过期。收到确认后不例行重发启动操作；重连时同步所有非终态任务，客户端根据本地记录报告已接收、正在运行或已完成。采用至少一次投递和幂等执行，不承诺分布式场景下严格执行一次。

客户端持久记录指令 ID、任务参数摘要、状态和结果 ID。重复指令返回已有状态，不能重复启动定时器。后台重复点击通过请求幂等键合并；同设备已有活动图片会话时返回现有会话。

网络失败使用带随机偏移的退避重连。401 进入重新认证，403 设备停用则终止业务任务；不得反复注册新身份逃避停用状态。

## iOS 推送和定位

普通 APNs 后台推送只能通知有待同步内容，可能延迟、合并或不送达，不用于每 10 秒维持连接。推送中不携带图片或定位数据，设备获得运行机会后通过认证接口同步。[APNs 后台通知依据](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app)

定位采用 Core Location。每条位置记录包含 WGS84 或明确声明的坐标系、经纬度、精度、来源、采集时间与服务器接收时间。地图适配层负责必要的坐标转换，不混用不同坐标系。未获取到新位置时保留旧位置及其原时间，不改成当前定位。

若承载 App 满足用户明确同意的定位共享条件，可以评估 Location Push Service Extension。它需要相应能力、独立定位推送注册及 Always 定位授权，并受系统推送额度限制，不能承载任意指令或高频心跳。[定位推送扩展依据](https://developer.apple.com/documentation/corelocation/creating-a-location-push-service-extension)

无定位权限、定位服务关闭、仅近似位置、暂时无法定位、请求超时和旧位置应分别返回状态。不能把当前位置不可用替换成未标注的 IP 估算位置。

## 实时图片会话

服务器发送一次启动操作，客户端自己按 3 秒目标间隔采集。WSS 发送控制与状态消息，PNG 走 HTTPS。界面渲染占用主线程的时间和 PNG 编码、上传时间分别计量，网络操作不能堵住界面线程。

会话同时记录期望状态和设备观察状态：

| 类型 | 状态 |
| --- | --- |
| `desired_state` | `running`、`stopped` |
| `observed_state` | `starting`、`running`、`waiting_foreground`、`waiting_permission`、`interrupted`、`stopped`、`failed` |

用户点击实时采集后，网页先显示等待手机回复。手机将任务保存到本地后确认接收，首张 PNG 上传成功后报告运行中。用户随后可以关闭网页，手机继续按 3 秒目标间隔执行；不使用观看者租约或网页续期。

第一版一个设备最多一个未结束任务。重复开始返回现有任务，不创建多个定时器；代理或总台可显式停止。重新打开网页后，从服务器查询原任务及最新图片，不额外启动采集。任务可以指定截止时间，也可以一直执行到停止指令。

任务状态版本递增，停止记录持久保存，迟到的开始消息不能恢复已结束任务；新任务使用新 ID。网络断开不结束手机已接收的任务，影响的是上传和收令；App 不活动或受保护数据不可用时暂停采集。恢复活动后继续未过期任务，连接恢复后同步停止、归属变化和待执行指令。设备停用或归属变化时结束旧任务。

每台设备至多一个采集任务和一个正在上传的实时帧。当前实现中，上一帧仍在编码或上传时跳过新的采集时机，不累积待传图片。每帧携带会话编号、分配批次、帧序号、采集时间、图片来源、应用运行状态和缓存标记。服务器按帧序号更新最新画面，迟到旧帧不得覆盖新帧。

按需图片和定时历史图片默认保留 7 天。实时帧默认仅维护最新一帧，同时每 30 秒抽存一张历史；是否全部留存由总台配置，页面明确显示留存策略。修改为全部留存前计算存储和带宽。

## UIKit 和屏幕状态

UIKit 界面渲染的前提是采集端能访问目标 App 自己的视图，并且进程有运行机会。视图存在不代表内容仍在更新；从背景残留视图生成的图片不等于当前系统屏幕。

第一版默认规则为：前台和有可用视图时采集；进入后台、采集环境不可用或系统中断时暂停，回报具体原因。回到前台后检查本地任务有效性并恢复，同时重连以同步停止和归属变化。缓存图片保留原采集时间并标记缓存，不能作为本次实时请求的新画面。

由自有 App 提供窗口选择接口，dylib 在采集时获取当前目标窗口。默认选择前台活动场景中唯一的 key window；多场景存在歧义时由 App 明确指定，不能任取一个窗口。每帧覆盖选定窗口的完整 bounds。窗口外的系统界面和其他窗口不合成进该帧。

## 数据模型

| 表 | 关键字段和约束 |
| --- | --- |
| `users` | ID、唯一账号、密码哈希、角色、启用状态、强制改密标记 |
| `login_sessions` | 用户、会话摘要、到期和撤销时间 |
| `devices` | ID、唯一设备标识、名称、停用状态、当前分配 ID、最近联系和各类上报时间 |
| 设备身份字段 | 当前设备表保存安装秘密摘要和设备令牌摘要，配合设备启用状态验证身份 |
| `assignments` | 设备、代理、开始和结束时间、分配人、递增归属版本；同设备最多一条未结束记录 |
| `commands` | ID、设备、归属版本、类型、参数、状态、有效期、操作人、幂等键、结果引用 |
| 指令投递状态 | 直接保存在 `commands` 中，含接收确认、最近发送时间、完成时间；指令先入库再发送 |
| `image_sessions` | 设备、分配批次、拥有者、期望和观察状态、版本、手机确认时间、可空任务截止时间、停止原因 |
| `image_reports` | 唯一报告 ID、设备、分配批次、命令或会话、帧序号、来源、采集与接收时间、文件、缓存标记 |
| `location_reports` | 唯一报告 ID、设备、分配批次、命令、经纬度、坐标系、精度、采集与接收时间 |
| `audit_logs` | 操作者、对象、动作、结果、时间、请求追踪号 |

设备和用户不物理删除已有历史引用。报告 ID 在同一设备内唯一；会话帧序号在同一会话内唯一。指令和图片按设备加时间建立查询索引，待投递事件按下一次尝试时间建立索引。业务时间存 PostgreSQL `timestamptz`，API 使用带时区的 RFC3339，网页默认显示北京时间。

文件对象名由服务器生成，不接受客户端路径。数据库状态与文件落盘通过暂存和提交步骤协调：先校验、限流和落盘暂存，再写入报告和指令结果；只有数据库提交成功才返回成功。对孤立临时文件、引用但丢失的文件和过期文件分别清理与告警。

## 页面和接口范围

总台页面包括工作台、待分配设备、全部设备、代理管理、图片和位置详情、指令记录、系统设置和审计日志。代理页面包括我的设备、设备详情、请求记录和个人设置。

设备详情的图片区显示来源、采集时间、接收时间、是否缓存和会话状态；位置区显示地图、采集时间与精度；连接状态与采集状态独立展示。画面中断后停留最后一帧并显示暂停原因，不伪装成实时更新。

| 接口组 | 用途 |
| --- | --- |
| `/api/v1/auth/*` | 登录、退出、改密 |
| `/api/v1/admin/agents/*` | 代理创建、重置密码、启用和禁用 |
| `/api/v1/admin/devices/*` | 全量设备、下发、回收、转移和停用 |
| `/api/v1/devices/*` | 按当前身份限制的列表、详情、图片、位置和指令 |
| `/api/v1/device/*` | 设备认证、连接、同步、心跳、结果和数据上报 |

请求结构和重连规则见 [设备通信协议](设备通信协议.md)。

## 容量和运维

每 3 秒一帧即每分钟约 20 张。以单张 PNG 为 500 KB 的假设计算，一台设备约 10 MB 每分钟、600 MB 每小时；100 台同时采集约 16.7 MB 每秒上传、约 133 Mbps，均未计协议开销和网页下行。图片大小必须以真机样本测量，不能用此假设直接作为采购依据。

首版设置图片字节数、像素数、单设备上传并发和接口速率上限；按容量选择默认输出尺寸。PNG 校验实际格式，不仅校验扩展名；检查解码资源占用，避免超大尺寸图片拖垮服务。

需要监控连接数、指令确认延迟、结果超时、实时帧间隔、上传队列、磁盘容量、清理失败及数据库连接数。数据库定期备份并验证恢复；文件保留和备份策略分别设置。服务重启后从数据库恢复待投递指令和任务状态，不因重启延长已有截止时间。

## 实施顺序和验收

1. 真机验证自有 App 加载 dylib：确定活动窗口提供接口，将当前活动 UIWindow 渲染为单张 PNG；测试弹窗窗口切换、长列表可见区域、WebView、视频区域、后台、锁屏、恢复和内存峰值。
2. 完成账号、角色、设备登记与分配，验证代理之间数据隔离。
3. 完成 WSS、心跳、指令数据库、幂等确认和重连同步，先用客户端模拟器验证协议。
4. 接入单次图片和定位，区分采集失败、权限不足、缓存和新结果。
5. 接入手机自主实时任务、3 秒调度、上传背压、暂停恢复和停止，验证关闭网页后继续运行。
6. 完成图片历史、地图、清理、审计、部署和恢复。

验收必须覆盖：未知设备进总台；下发后仅指定代理可见；断线重连不丢归属；同指令多次送达不启动重复任务；服务器重启不丢待执行指令；过期任务不补执行；停止后迟到开始消息无效；后台或锁屏后画面明确暂停；缓存不冒充新图；转移设备后旧代理立即失去服务端访问权限；旧批次上报不泄露给新代理；新帧不被旧帧覆盖。

## 尚需确定的部署输入

- 自有 App 的工程接入点、dylib 加载方式、活动窗口提供接口和场景选择规则。
- 实际 iPhone 型号、iOS 版本及客户端运行和安装方式；工程最低版本设置不等于设备实测版本。
- 设备数量、同时观看数量、图片尺寸和实际 PNG 大小。
- 定位是单次刷新还是持续共享，实际权限和配套 App 能力。
- 注册凭据的部署方式、服务器域名、历史保留时间和备份目的地。
