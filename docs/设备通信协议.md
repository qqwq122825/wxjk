# 设备通信协议

本协议服务于总台和代理两级后台。设备仅识别自身身份和服务器下发的分配版本，无需保存代理登录账号。接口基础路径统一为 `/api/v1/device`，正式环境只接受 HTTPS 和 WSS。

第一版图片采集端是自有 App 内加载的 dylib。图片源为 `uikit_window`，采集范围为 `active_window`，一次生成当前活动 UIWindow 的一张 PNG。

## 身份和通用规则

所有设备业务接口使用 `Authorization: Bearer <device_token>`。设备令牌只授权该设备，不能调用网页管理接口。设备 ID 在令牌解析后由服务端确定；请求内如带设备 ID，必须匹配。

客户端保存稳定设备 ID、设备令牌和未完成指令记录。日志不写完整令牌、登录密码或图片内容。APNs 设备 Token 与本系统设备令牌是不同凭据，不能互换。

时间统一使用带时区的 RFC3339，例如 `2026-11-11T14:30:00+08:00`。服务端接收时间用于判断通信新鲜度，采集时间用于呈现数据年龄。指令的 `expires_at` 限制首次接受时间；独立的 `task_expires_at` 限制手机任务运行时间，两者不能混用。

错误响应形如：

```json
{
  "error": {
    "code": "COMMAND_EXPIRED",
    "message": "指令已过期",
    "request_id": "req_example"
  }
}
```

示例中的 ID 均为占位值。线上 ID 由双方按字段约定生成，不能从示例推断身份或访问权限。

## 首次注册

`POST /api/v1/device/register`

注册请求包含本地安装标识及首次生成并保存在 Keychain 的随机 `registration_secret`。服务端登记新安装时绑定秘密的哈希，重试已有安装的注册必须验证秘密，不能仅凭已有设备 ID 返回身份令牌。设备令牌只能用于该设备上报与收令。

准入策略由服务端决定：开放新设备登记时，新设备进入总台待审批池并限制上报额度；受控部署时额外要求 `enrollment_token`，限制其有效期和登记数量。客户端支持这两种部署方式，只向用户询问服务器地址。

```json
{
  "enrollment_token": "部署时提供的注册凭据",
  "installation_id": "客户端持久保存的安装标识",
  "registration_secret": "首次生成的32字节随机秘密的Base64编码",
  "platform": "ios",
  "os_version": "15.6",
  "client_version": "0.1.0",
  "capabilities": {
    "capture_sources": ["uikit_window"],
    "capture_scopes": ["active_window"],
    "location": false,
    "location_push": false
  }
}
```

`capabilities` 是客户端报告的能力描述，不代替服务端权限和实际执行检查。返回示例：

```json
{
  "device_id": "dev_example",
  "device_token": "仅在登记或轮换时返回的凭据",
  "server_time": "2026-11-11T14:30:00+08:00",
  "heartbeat_interval_seconds": 30,
  "assignment": {"id": null, "version": 0}
}
```

未知设备在总台显示待分配。重复登记不能绕过既有停用状态；凭据遗失时走恢复或重新登记规则。

## 建立连接和同步

`GET wss://服务器域名/api/v1/device/ws`

原生客户端在握手请求头携带设备令牌，不把长期令牌放进 URL。服务端分配 `connection_id`，返回服务器时间和配置。客户端随后发送 `device.hello`，包含启动标识、客户端版本、能力、应用状态、已知归属版本及本地非终态指令摘要。

服务端返回 `device.sync`，必须包含 `assignment` 对象及 `commands` 数组。`assignment.id` 可以为 null，`assignment.version` 为非负整数。`commands` 包含需确认或重新投递的未过期完整指令，包括尚未送达的停止指令。已被手机接收的实时任务独立运行，WSS 重连不创建新任务。

```json
{
  "type": "device.sync",
  "assignment": {"id": null, "version": 0},
  "commands": []
}
```

每次新连接替换该采集端旧连接。旧连接消息及关闭事件不能覆盖新代次的状态。长时间没有应用层心跳的 Socket 不能仅凭 TCP 仍存在而保持在线。

## 心跳和状态

WSS 消息为 `device.heartbeat`；HTTPS 兜底为 `POST /api/v1/device/heartbeat`。客户端运行期间每约 30 秒发送，加入少量随机偏移。一次请求失败不会立即认定离线。

```json
{
  "type": "device.heartbeat",
  "message_id": "msg_example",
  "connection_id": "conn_example",
  "app_state": "foreground",
  "screen_state": "unknown",
  "capture_state": "ready",
  "assignment_version": 3,
  "config_version": 2
}
```

`app_state` 可为 `foreground`、`inactive`、`background`、`unknown`。`screen_state` 未经可靠获取时为 `unknown`，不能把 App 进入后台直接写为手机锁屏。能力和权限变化时主动发送状态更新。

WSS 心跳同时发送 WebSocket ping，10 秒未收到 pong 则关闭旧连接并重连。当前 iOS 实现通过 WSS 发送心跳，HTTPS 心跳接口保留为后续兜底扩展，不用于后台保活。

## 指令结构

```json
{
  "type": "command.dispatch",
  "command_id": "cmd_example",
  "device_id": "dev_example",
  "assignment_id": "asg_example",
  "assignment_version": 3,
  "command": "GET_IMAGE",
  "created_at": "2026-11-11T14:30:00+08:00",
  "expires_at": "2026-11-11T14:32:00+08:00",
  "parameters": {
    "capture_source": "uikit_window",
    "capture_scope": "active_window",
    "allow_cached": false,
    "max_long_edge_px": 1280
  }
}
```

指令参数由命令类型限定，不接受任意代码、文件路径或任意网络请求作为参数。`max_long_edge_px` 是输出尺寸上限示例，实际默认值需按画面可读性验证。

| 指令 | 主要参数 |
| --- | --- |
| `GET_IMAGE` | `capture_source=uikit_window`、`capture_scope=active_window`、`allow_cached`、输出尺寸 |
| `GET_LOCATION` | 最大位置年龄、期望精度、超时时间 |
| `START_IMAGE_SESSION` | 会话 ID、会话版本、窗口图片来源和范围、采集间隔、可选任务截止时间 |
| `STOP_IMAGE_SESSION` | 会话 ID、递增会话版本、停止原因 |

客户端核对设备、当前分配版本、有效期、能力和本地执行记录后，先持久化接收状态再确认。过期、取消或旧归属指令不能启动任务。无法确认当前有效性时先同步服务器。

## 指令确认和结果

WSS 使用 `command.ack` 和 `command.progress`；HTTPS 对应 `POST /commands/{id}/ack`、`POST /commands/{id}/progress`。

```json
{
  "type": "command.ack",
  "command_id": "cmd_example",
  "status": "received"
}
```

接收确认不代表完成。进度可为 `running`、`waiting_foreground` 或 `waiting_permission`，并带机器可读原因。完成信息通过 `POST /commands/{id}/result` 提交，图片和定位接口也可在同一数据库事务内写入对应结果。

单次采集只有在数据文件和数据库记录成功提交后才返回 `succeeded`。指令编号和报告编号共同去重；重试返回已有结果引用。失败示例：

```json
{
  "result_id": "result_example",
  "status": "failed",
  "error_code": "CAPTURE_UNAVAILABLE",
  "error_message": "目标视图当前不可用于采集"
}
```

每次投递等待约 10 秒，连接可用而未确认时重投同一指令。已确认任务在断线恢复时交换执行摘要；服务端终态优先，客户端不能恢复已停止会话。

## 单次图片和实时帧

`POST /api/v1/device/images`，请求类型为 `multipart/form-data`，包含 `metadata` JSON 和 `image` PNG。

单次请求带 `command_id`；实时帧带 `session_id`、`session_version` 和递增 `frame_seq`。所有图片均带设备分配 ID 和版本，服务端从认证上下文校验，不相信客户端自行声明的代理。

```json
{
  "report_id": "report_example",
  "command_id": null,
  "session_id": "session_example",
  "session_version": 1,
  "frame_seq": 12,
  "assignment_id": "asg_example",
  "assignment_version": 3,
  "capture_source": "uikit_window",
  "capture_scope": "active_window",
  "captured_at": "2026-11-11T14:30:36+08:00",
  "app_state": "foreground",
  "is_cached": false,
  "pixel_width": 720,
  "pixel_height": 1280
}
```

服务端校验报告 ID、会话状态、批次、尺寸和实际图片格式。客户端声明尺寸需与解码尺寸匹配。服务端生成文件名和 `received_at`。同会话迟到的旧帧不能替换最新帧。

缓存必须携带原采集时间和 `is_cached=true`。`allow_cached=false` 时，缓存图片不能使单次新图请求成功。正常输出覆盖选定窗口的完整可见区域；不逐张导出页面中的图片对象，不拼接滚动范围外的内容。

## 位置上报

`POST /api/v1/device/locations`

```json
{
  "report_id": "location_example",
  "command_id": "cmd_location_example",
  "assignment_id": "asg_example",
  "assignment_version": 3,
  "latitude": 31.2304,
  "longitude": 121.4737,
  "coordinate_system": "WGS84",
  "horizontal_accuracy_m": 25,
  "collected_at": "2026-11-11T14:30:02+08:00",
  "source": "core_location"
}
```

坐标仅为格式示例。Core Location 不一定能给出确定的 GPS、Wi-Fi 等底层来源，不应编造来源值。经度范围为 -180 到 180，纬度为 -90 到 90。无效定位、负精度或明显异常时间返回具体错误，不伪造为零坐标。

单次请求按最大位置年龄判断结果是否合格；旧坐标可以作为历史显示，但不能标记为新定位。持续定位数据也关联有效分配批次；图片和位置各自上传、各自去重，一类失败不阻塞另一类。

## 实时会话同步

设备运行期间最多一个活动图片任务。服务端和手机均持久保存任务状态。开始和停止关联同一会话 ID；停止时版本必须更高，重复开始不重置帧序号和任务截止时间。已结束 ID 不复用。

手机保存开始任务后返回 `accepted` 或 `waiting_foreground`，这表示任务已接受；收到首张上传成功的画面后，通过 `device.capture_state` 报告 `running`。网页可在确认接受或运行后关闭，不发送自动停止，不需要续期。

`parameters.task_expires_at` 可为空或省略，表示运行到显式停止；指定时使用 RFC3339 日期。手机运行期间用连续单调时钟检查截止，进程重启时从持久保存的截止日期恢复。后台或锁屏时暂停，活动恢复时继续未结束任务。服务端拒绝已停止或旧归属任务的新上传。

WSS 指令结果采用 `command.result` 消息，含 `result_id`、`command_id`、`status` 和结果字段。服务器保存结果后返回 `command.result_ack` 及 `command_id`；手机重连时重发尚未确认的结果。`device.disabled` 或 `auth.invalid` 消息让客户端停止重连并终止采集任务。

## 主要错误码

| HTTP 状态 | 错误码 | 处理 |
| --- | --- | --- |
| 400 | `INVALID_PAYLOAD` | 修正字段，不盲目重试 |
| 401 | `DEVICE_UNAUTHENTICATED` | 恢复认证，停止正常业务重试 |
| 403 | `DEVICE_DISABLED` | 停止业务任务，等待管理员处理 |
| 409 | `ASSIGNMENT_CHANGED` | 停止旧批次任务，重新同步 |
| 409 | `SESSION_VERSION_MISMATCH` | 以服务器会话状态为准 |
| 410 | `COMMAND_EXPIRED`、`SESSION_EXPIRED` | 不执行，不继续上传 |
| 413 | `IMAGE_TOO_LARGE` | 降低输出尺寸或修正配置 |
| 422 | `UNSUPPORTED_CAPTURE_SOURCE` | 上报能力不匹配 |
| 422 | `CAPTURE_UNAVAILABLE`、`LOCATION_UNAVAILABLE` | 返回具体采集原因 |
| 422 | `CAPTURE_INCOMPLETE` | 界面存在缺失区域，不能作为完整画面成功返回 |
| 422 | `CAPTURE_TARGET_AMBIGUOUS` | 存在多个可选活动窗口，由自有 App 明确目标后重试 |
| 429 | `RATE_LIMITED` | 遵守 `Retry-After`，合并待传中间帧 |
| 503 | `SERVICE_UNAVAILABLE` | 有上限的退避和随机偏移重试 |

等待前台或授权用任务进度表示；用户拒绝、等待超时或任务已过期后形成终态。网络传输重试与重新启动业务任务分开处理。
